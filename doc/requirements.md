# locale_sheet 要件定義

このドキュメントは `locale_sheet` が満たすべき要件を1か所にまとめたものです。
これまで要件は README（利用方法）、`example/README.md`（ロケール列の判別ルール）、`doc/developer/README.md`（フォーマットの開発メモ）、`CHANGELOG.md`（機能の履歴）、そしてコードとテストに分散していました。本書はそれらを統合し、実装との対応関係を明示することを目的とします。

**本書の位置づけ**

- 各要件には ID（`FR-xx` / `NFR-xx`）を振り、実装とテストの参照先を併記します。仕様を変更する際は、本書・実装・テストの3点を揃えて更新してください。
- 利用者向けの説明は `README.md` / `README_ja.md`、開発手順は `doc/developer/README.md` が引き続き担当します。本書は「何を満たすか」に限定し、手順や使い方は重複させません。
- 記述は 0.4.1 時点の実装に基づきます。

---

## 1. 用語

| 用語 | 定義 |
| --- | --- |
| シート | XLSX ワークブック内の1つのワークシート |
| ヘッダ行 | シートの1行目。列の意味を決める |
| キー | `key` 列の値。リソースの識別子になる |
| ロケール列 | ヘッダがロケールタグとして妥当な列。翻訳値を持つ |
| 説明列 | `--description-header` で指定されたヘッダを持つ列。ロケール列から除外される |
| エントリ | シートの1データ行に対応する `LocalizationEntry` |
| プレースホルダ | メッセージ中の `{name}` 形式の差し込み記法 |
| 有効なデフォルトロケール | フォールバック元およびメタデータ出力先として選ばれた1つのロケール |

## 2. スコープ

### 2.1 対象

- XLSX ファイルを唯一の情報源として、ローカライズ文字列を出力形式に変換すること
- CLI とライブラリの両方から利用できること
- 出力形式は現時点で ARB のみ。ただし新しい形式を追加できる構造であること

### 2.2 対象外

以下は現時点で意図的に扱いません。実装する場合は本書の更新を伴う仕様変更として扱います。

- XLSX の書き出し（本パッケージは読み取り専用）
- `.xls`（旧形式）、CSV、Google スプレッドシート API などの入力
- 複数シートの同時変換（1回の実行で扱うシートは1つ）
- 翻訳の自動生成・機械翻訳
- ARB 以外の出力形式の同梱実装
- 複数形（ICU plural / select）の解釈。プレースホルダは名前の検出のみ行う

## 3. 機能要件

### 3.1 入力とシート選択

| ID | 要件 |
| --- | --- |
| FR-01 | XLSX 形式のバイト列を入力として受け付ける。CLI はファイルパスから読み込む |
| FR-02 | シート名を指定できる。省略時はワークブックの最初のシートを使う |
| FR-03 | シート名の一致判定は大文字小文字を区別する（`Sheet1` と `sheet1` は別物） |
| FR-04 | 指定したシートが存在しない場合は `SheetNotFoundException` を投げ、例外は利用可能なシート名の一覧を保持する |
| FR-05 | ワークブックにシートが1つも無い状態でシート名を省略した場合も FR-04 と同じ扱いとする |
| FR-06 | 行が1行も無いシートは、ロケールもエントリも空の結果として正常に返す（エラーにしない） |

実装: `lib/src/core/parser.dart` / テスト: `test/src/core/parser_test.dart`

### 3.2 ヘッダ行の解釈

| ID | 要件 |
| --- | --- |
| FR-10 | ヘッダ行は1行目とする |
| FR-11 | 1列目のヘッダは `key` でなければならない。前後の空白は無視し、大文字小文字は区別しない。満たさない場合は `FormatException` |
| FR-12 | ロケール列を明示指定できる。指定した場合、それ以外の列はロケールとして扱わない。一致判定は前後の空白と大文字小文字を無視し、`-` と `_` を同一視する。指定したタグが1行目に存在しない場合は `FormatException`（綴り間違いで言語が黙って欠落することを防ぐ） |
| FR-12a | 明示指定が無い場合、2列目以降のうちヘッダがロケールタグとして妥当な列をロケール列として採用する。この判定は緩く、`memo` のような一般的な列名も該当し得る（FR-34 の言語サブタグ定義による） |
| FR-13 | ロケール列として採用しなかったヘッダ（空ヘッダを除く）を記録し、呼び出し側が取得できるようにする。無視した列があっても後続のロケール列の対応がずれてはならない |
| FR-13a | 正規化すると同一になるロケール列（区切り文字違い・大文字小文字違い）が複数ある場合は `FormatException`。BCP 47 では区切り文字と大文字小文字は有意でないため、同じロケールを2列に書いた入力ミスとして扱う |
| FR-14 | 説明列が指定された場合、その列はロケール列の判定から除外する |
| FR-15 | 説明列のヘッダ指定は前後の空白を無視し、大文字小文字を区別せずに一致判定する |
| FR-16 | 説明列として `key` を指定した場合は `FormatException`（1列目は必ずキー列のため、指定ミスとみなす） |
| FR-17 | 説明列として指定したヘッダがロケールタグとして妥当な場合は `FormatException`（ロケール列を誤って説明列にする事故を防ぐ） |
| FR-18 | 説明列として指定したヘッダが1行目に存在しない場合は `FormatException` |
| FR-19 | ロケールの順序はヘッダ行の左から右の並びを保持する |

FR-13 は列の対応付けを列インデックスで保持することで満たします（ロケール名のリストと列インデックスのリストを対にして持つ）。

### 3.3 データ行の解釈

| ID | 要件 |
| --- | --- |
| FR-20 | 2行目以降をデータ行として扱う |
| FR-21 | 空行、およびキーが空文字（空白のみを含む）の行はスキップする |
| FR-22 | 空セルはその言語の翻訳が未提供であることを示し、`null` として保持する |
| FR-23 | 説明セルが空または空白のみの場合、説明は `null` とする |
| FR-24 | 行の長さがロケール列のインデックスに満たない場合も、欠落セルを未提供として扱いエラーにしない |
| FR-25 | 同じキーが複数行に現れても解析はエラーにしない。エントリは行ごとに生成され、出力時にロケールごとに後の行が優先される |
| FR-26 | 複数行に現れたキーの一覧を取得できる。CLI は該当キーごとに警告を出力し、処理は継続する（終了コードは変えない） |

### 3.4 ロケールタグ

| ID | 要件 |
| --- | --- |
| FR-30 | ロケールタグは BCP 47 に準じた実用的な緩い検証を行う。`language` / `language-script` / `language-region` / それらの組み合わせと追加のバリアントを受け付ける |
| FR-31 | 区切り文字は `-` と `_` を等価に扱う（`zh-Hant-HK` と `zh_Hant_HK` は同一とみなす） |
| FR-32 | 前後の空白は取り除いて評価する |
| FR-33 | 空白・`/`・`\`・`.` を含むタグは不正とする |
| FR-34 | 言語サブタグは英字2〜8文字であること |
| FR-35 | ARB 出力に使うタグは、加えてファイル名として安全であること。先頭のドット、連続ハイフン、先頭末尾のハイフン、英数字とハイフン・アンダースコア以外の文字を含むタグは拒否する |
| FR-36 | Windows の予約デバイス名（`CON`, `PRN`, `AUX`, `NUL`, `COM1`〜`COM9`, `LPT1`〜`LPT9`）に該当するタグ、およびそれらと一致するファイル名になるタグは拒否する |

実装: `lib/src/core/model_helpers.dart`（`normalizeLocaleTag` / `isValidLocaleTag` / `isSafeArbLocaleTag`）

> FR-30〜FR-34 はパース時の列判定に、FR-35〜FR-36 は出力時の検証に使われます。パースを通ったタグが出力時に拒否されることがあり得ます（例: ヘッダ `CON`）。

### 3.5 デフォルトロケールとフォールバック

| ID | 要件 |
| --- | --- |
| FR-40 | 有効なデフォルトロケールを1つ決定する。CLI では明示指定があればそれを使い、シートに存在しなければエラーとする |
| FR-41 | 未指定の場合、シートに `en` があれば `en`、無ければ最初のロケール列を採用する。ロケール列が1つも無い場合は `en` を採用するが、CLI は FR-85a によりその前にエラーとするため、この分岐はライブラリ経由でのみ到達する |
| FR-42 | ある言語の翻訳が未提供のとき、デフォルトロケールの翻訳が存在すればそれで補完する。補完できない場合、そのキーはその言語の出力に含めない |

### 3.6 プレースホルダ

| ID | 要件 |
| --- | --- |
| FR-50 | メッセージ本文から `{name}` 形式のプレースホルダを検出できる。名前は英字またはアンダースコアで始まり、以降は英数字とアンダースコア |
| FR-51 | `{{` および `}}` はエスケープとして扱い、プレースホルダとして検出しない |
| FR-52 | 自動検出は既定で無効。利用者が明示的に有効化した場合のみ動作する |
| FR-53 | 未宣言のプレースホルダを検出したときの扱いを `warn` / `ignore` / `add` / `error` から選べる。既定は `warn` |
| FR-54 | `add` を選んだ場合、検出したプレースホルダをモデルに追加し `source` を `detected` とする。型は利用者が指定でき、既定は `String` |
| FR-55 | 1つのメッセージに複数のプレースホルダがある場合、すべてを蓄積する（後の検出が先の検出を上書きしない） |
| FR-56 | すでに宣言済みのプレースホルダは再追加も警告もしない |
| FR-57 | 自動検出を有効にせずに未定義時の扱いだけを指定した場合、そのオプションが無視される旨を警告する |

実装: `lib/src/core/placeholder_detector.dart`, `lib/src/cli/export_runner.dart` / テスト: `test/src/core/placeholder_detector_test.dart`, `test/src/cli/export_runner_test.dart`

### 3.7 ARB 出力

| ID | 要件 |
| --- | --- |
| FR-60 | 出力先ディレクトリが存在しない場合は再帰的に作成する |
| FR-61 | ロケールごとに1ファイルを出力する。ファイル名は `app_<tag>.arb`。`<tag>` はハイフンをアンダースコアに置換したもの（例: `zh-Hant-HK` → `app_zh_Hant_HK.arb`） |
| FR-62 | `@@locale` にはファイル名と同じ正規化済みタグ（アンダースコア区切り）を設定する。ヘッダの生文字列ではない |
| FR-63 | 出力を開始する前に全ロケールを検証する。ファイル名として安全でないタグ、および同一のファイル名になる複数のロケールを検出した場合は `FormatException` を投げ、**1ファイルも書き出さない**。出力先ディレクトリも作成しない |
| FR-63a | ファイル名の重複判定は大文字小文字を区別せずに行う。大文字小文字を区別しないファイルシステムでの上書きを防ぎ、ファイルシステムによって出力が変わることを避けるため |
| FR-64 | 翻訳キーはアルファベット順に並べる。`@@locale` は末尾に置く |
| FR-65 | `@<key>` メタデータは有効なデフォルトロケールのファイルにのみ出力する。他のロケールのファイルには含めない |
| FR-66 | デフォルトロケールのファイルでは、値を持つ各キーに対して `@<key>` オブジェクトを出力する。説明もプレースホルダも無い場合は空オブジェクトとする |
| FR-67 | `@<key>` は対応する翻訳キーの直前に配置する（Flutter/ARB の慣例） |
| FR-68 | 説明がある場合は `@<key>.description` に出力する |
| FR-69 | プレースホルダがある場合は `@<key>.placeholders` に名前→オブジェクトの形で出力する。各オブジェクトは少なくとも `type` を持ち、`example` と `source` は存在する場合のみ含める |
| FR-70 | JSON は2スペースインデントで整形する |

実装: `lib/src/exporters/arb_exporter.dart` / テスト: `test/src/exporters/arb_exporter_test.dart`

### 3.8 CLI

| ID | 要件 |
| --- | --- |
| FR-80 | `export` サブコマンドを提供する |
| FR-81 | 入力パスは必須。出力形式の既定は `arb`、出力先の既定はカレントディレクトリ |
| FR-82 | サポートされていない出力形式を指定した場合はエラーとし、処理を行わない |

| FR-85a | ロケール列が1つも無い場合はエラーとし、出力を行わない。ファイルを1つも生成していないのに成功として報告しない。エラーメッセージには無視した列と `--locales` による回避策を含める |

## 5. 終了コード

| コード | 意味 | 発生条件 |
| --- | --- | --- |
| `0` | 正常終了 | 変換に成功した |
| `1` | 実行時エラー | ファイル I/O 失敗、`FormatException` を含む解析・出力時の例外、`--treat-undefined-placeholders=error` での未定義プレースホルダ検出 |
| `64` | 利用方法の誤り | 引数の解析失敗、未サポートの出力形式、指定シートが存在しない、指定したデフォルトロケールがシートに存在しない、ロケール列が1つも無い |

## 6. 主なエラー条件

| 条件 | 例外 / 終了コード |
| --- | --- |
| 1列目のヘッダが `key` でない | `FormatException` / `1` |
| 説明列のヘッダが見つからない | `FormatException` / `1` |
| 説明列に `key` を指定した | `FormatException` / `1` |
| 説明列のヘッダがロケールタグと衝突する | `FormatException` / `1` |
| 明示指定したロケール列が1行目に無い | `FormatException` / `1` |
| ロケールタグが ARB ファイル名として不正 | `FormatException` / `1` |
| 正規化すると同一になるロケール列が複数ある | `FormatException` / `1` |
| 指定シートが存在しない | `SheetNotFoundException` / `64` |
| 指定したデフォルトロケールがシートに無い | （例外なし・エラーログ）/ `64` |
| 未サポートの出力形式 | （例外なし・エラーログ）/ `64` |

## 7. 拡張ポイント

新しい出力形式を追加する場合は、次の3点のみで完結することを要件とします。

1. `LocalizationExporter` を実装したクラスを `lib/src/exporters/` に追加する
2. `ExportCommand` のエクスポーター表に登録する（表のキーが `--format` に指定する値になる）
3. 1:1 のテストファイルを追加する

コア（`lib/src/core/`）とパーサに手を入れる必要がある場合、それは出力形式の追加ではなく入力仕様の変更であり、本書の更新を伴います。

## 8. 既知の制限

本書の要件を満たしたうえで、現時点で残っている制限です。将来対応する場合は要件として追記します。

- 重複キーは警告されるが解決されない（FR-26）。エクスポート時にロケールごとに独立して後勝ちで上書きされ、かつ空セルは上書きしないため、行によって空セルの位置が異なると、言語ごとに別の行の値が採用されることがある。
- 1回の実行で変換できるシートは1つに限られる。複数シートをまとめて出力する手段は無い。
- CLI は `Exception` のみを捕捉する。`Error`（`StackOverflowError` など）が発生した場合は捕捉されず、Dart 既定の異常終了となる。
- ロケールタグの検証は緩い実用的なチェックであり、レジストリに登録された言語・地域コードかどうかは検証しない。そのため自動判定では `memo` `note` `comment` `status` `id` のような英字2〜8文字の列名もロケールとして扱われる。回避するには FR-12 の明示指定を使う。
- セル値は文字列化して扱うため、日付セルは ISO 8601 形式の文字列として取り込まれる。

## 9. 変更時の運用

- 仕様を変更する PR では、本書の該当 ID を更新し、PR 本文でどの要件が変わったかを明示すること。
- 要件を追加する場合、ID は各節の連番の末尾に採番し、既存 ID の番号は再利用しない（過去の PR からの参照が壊れるため）。
- 「対象外」「既知の制限」に挙げた項目を実装する場合は、該当行を削除して機能要件へ移すこと。
